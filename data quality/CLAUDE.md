# Compendium data quality

Part of the same repository as the pipeline, which lives one level up in
`../`. Nothing here changes the data — it only measures it and reports.

| File | What it does |
|---|---|
| `Compendium_Data_Gaps.ipynb` | Measures completeness, writes `data_gaps_report.xlsx` and regenerates `docs/data.js` |
| `Compendium_Data_Quality.ipynb` | Structural checks on raw questionnaires, and contradiction checks on the final files, into `data_quality_report.xlsx` |
| `../docs/index.html` | The dashboard. Static — open it directly or publish with GitHub Pages |
| `../docs/data.js` | The dashboard's data, regenerated by the gaps notebook |

Both notebooks read the final long files in `COMPENDIUM-ARAB SOCIETY\`,
produced by the pipeline notebooks in `../`. Run the pipeline first.

## Publishing the dashboard

The dashboard lives at the repository root in `../docs/`, because GitHub Pages
can only serve a branch root or a `/docs` at that root. On GitHub:
**Settings → Pages → Source: `master` branch, `/docs` folder**. It has no build
step and no dependencies, so it also works by opening `../docs/index.html` from
disk.

Re-run the last cell of the gaps notebook after new data, commit
`../docs/data.js`, and the published page updates.

## How completeness is measured — and why not a fill rate

Only 9–18% of rows in the long files carry a value. That number is **not** a
completeness figure and must never be reported as one: the questionnaire grid is
every age group × marital status × nationality × year, whether or not the
combination was ever intended to be filled.

Two levels are used instead:

**Level 1 — series completeness.** For each indicator × country, how many of the
17 expected years (2010–2026) carry a value at all, and separately how many
carry a *headline* value with every breakdown at its total.

**Level 2 — disaggregation availability.** Which breakdowns a country actually
supplies for an indicator.

On the current data that gives ~53% mean coverage, against the meaningless 14%.

## Things that look wrong but are deliberate

- **Seven dimensions have no total category** — causes of death, economic
  activity, employment status, main occupation, institutional sector, reasons
  for inactivity, the ICD list. An indicator broken down that way has no
  meaningful aggregate row, so its headline coverage is blank *by design*, not
  as a gap. `TOTAL_LABELS` lists only the dimensions that do have one.
- **2027–2030 are excluded from the expected range.** They exist as projection
  columns in the template; counting them would make every country look
  incomplete.
- **Spikes are compared after collapsing to one value per series per year.** The
  same dimensions and year can appear twice in these files, and without that
  step the comparison pits two rows from the *same* year against each other.
- **`Value` is parsed with `to_number()`, not `float()`.** Only 337 of 33,968
  population cells are numeric; the rest are text like `' 701 956 '` using
  spaces as thousand separators.
- **The dashboard payload is index-referenced arrays, not objects.** As objects
  it is ~1.5 MB; as arrays with a lookup table it is ~220 KB.

## What the checks have found

- **Two Population indicators labelled "(%)" hold absolute head-counts** for
  eight countries each, values up to 29,258,382. This is the single biggest data
  problem and needs fixing at source.
- **Coverage is very uneven by country** — roughly 10% for Djibouti against 72%
  for Qatar.
- **Poverty is the weakest chapter**, around 19% mean coverage.
- **133 series report nothing after 2019.**

## Conventions

- `pandas` with `openpyxl`, `pathlib.Path` for every path — the paths contain
  spaces.
- The dashboard is vanilla HTML/CSS/JS with no dependencies, so it works
  offline and on Pages without a build step.
- Dark theme by design. Colours are validated steps: a single blue ramp for
  magnitude, status hues for severity, and every status also carries a word so
  nothing depends on colour alone.
- Read-only. If a change to the data is ever needed, it belongs in the pipeline
  project, not here.
