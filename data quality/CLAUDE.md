# Compendium data quality

Part of the same repository as the pipeline, which lives one level up in
`../`. One notebook, `Compendium_Data_Quality.ipynb`. Nothing here changes
the data on its own — the checks only measure and report, and the one file
that can lead to a change is changed by a person's own decision, read back
from a file they saved themselves.

| File | What it does |
|---|---|
| `Compendium_Data_Quality.ipynb` | Part 1 reads the **raw questionnaires**, writes `data_quality_review.txt` and one `Data quality issues before pipeline execution_<Chapter>.txt` per chapter. Part 2 reads the **final long files**, writes `data_gaps_report.xlsx` and regenerates `docs/data.js` |
| `../docs/index.html` | The dashboard. Static — open it directly or publish with GitHub Pages |
| `../docs/data.js` | The dashboard's data, regenerated by Part 2's last cell |

Rewritten 10 September 2026: used to be two notebooks (structural checks on
the questionnaires + contradiction checks on the final files). Now one, in
two parts that share nothing but a file — Part 1 never reads a final file,
Part 2 never reads a raw one — so either can be run alone.

## Part 1 — the raw questionnaires, and the review-and-apply loop

Reads every raw questionnaire — the same files notebook 1 reads:

1. **Labels not in the dictionary, exactly** — a column name or value with no
   exact match, in either language. Below `FUZZY_MATCH_CUTOFF` is
   deliberate: a label the real pipeline would fix on its own needs no
   review.
2. **Values that are not plain numbers, and that `clean_one_value()` could
   not make sense of on its own** — a unit phrase, a placeholder, a sum are
   all handled automatically and need no review either; this is only the
   residue.
3. **Structural problems** — reporting only: a duplicate column header, a
   stray space in a merge key, a sheet with no `index` row that is not a
   recognized cover tab. Fixed in the source Excel file, not here.

**`data_quality_review.txt`** (beside the per-chapter
`pipeline_inconsistencies_<Chapter>.txt` files) is the action file. Every
finding in sections 1 and 2 gets a `CORRECTION:` line, pre-filled with a
suggestion where there is one. A person edits the file directly — accept,
retype, or `SKIP` — saves it, and tells Claude `apply <file>`.
`apply_review()` re-reads that exact file and writes the decisions to
`translation dict.xlsx` (labels) and `value corrections.xlsx` (values, in
`DATA COLLECTOR\`) — both idempotent and backed up first, the same pattern as
notebook 4's `update_dictionary()`. Nothing is written by any other path.

**`Data quality issues before pipeline execution_<Chapter>.txt`**, one per
chapter, is a separate, read-only summary — `write_chapter_reports()`, added
22 September 2026. Not aggregated across chapters the way
`data_quality_review.txt`'s findings are (the same mistyped header found in
both Housing and Poverty gets its own line in each chapter's file, not one
merged entry) and never asks for a correction — `apply_review()` doesn't read
it. Each finding is one line: `Country | Sheet | Indicator | Year | reason`.
Label and structural findings are about a column, a citation, or a whole
sheet rather than one row, so Country/Indicator/Year print as `-` for those;
only a value finding has a row to point at.

**`CHAPTERS = None` picks up every folder `discover_chapters()` finds**,
which currently includes two that are not real chapters —
`datacollector_received_quest_AR\yemen\` (Yemen's five questionnaires, one
folder level too shallow) and `country excel sheets` (two unsorted files).
Both get scanned and reported on as if they were chapters, which is why a
full run's structural-problem count looks alarming — most of it is `yemen`.
See Known issues in `../CLAUDE.md`. Set `CHAPTERS` to the real chapter list
explicitly to skip both.

## Part 2 — the final files: completeness, contradictions, the dashboard

Reads every `<Chapter>_EN.xlsx` in `merged_long_files\` and, per chapter, in
one pass:

**Completeness.** For every indicator × country, how many of the 17 expected
years (2010–2026) carry a value at all, and separately how many carry a
*headline* value with every breakdown at its total — and which breakdowns a
country actually supplies for an indicator.

Only 9–18% of rows in the long files carry a value, and that number is **not**
a completeness figure and must never be reported as one: the questionnaire
grid is every age group × marital status × nationality × year, whether or not
the combination was ever intended to be filled. Series are banded instead —
`none` / `sparse` (1-6 points) / `partial` (7-12) / `strong` (13-16) /
`complete` (17) — never averaged into one number, because a one-point series
and a seventeen-point series must never be allowed to cancel out into
something that reads as "half full".

**Contradictions**, six kinds, all through `measure_chapter()`'s `issues`:
a reported total that does not match the sum of its own parts (`total
mismatch`), a year-on-year change of more than `SPIKE_FACTOR` (`spike`), a
percentage indicator that also holds absolute counts (`units`), a percentage
breakdown that does not add to 100 within `PERCENT_TOLERANCE` (`percentages
do not sum to 100`), a negative value or a percentage outside 0-100
(`implausible value`), and the same row reported twice with two different
values (`conflicting duplicate rows`). Nothing here suggests a correction the
way Part 1 does — a contradiction in the FINISHED data is a finding about the
SOURCE, and fixing it means going back to the questionnaire.

**The dashboard**'s data, `docs/data.js`, is regenerated from the same
`SERIES` / `DIMENSIONS` / `ISSUES` the report is built from, as
index-referenced arrays rather than objects — repeating "chapter" /
"indicator" / "country" as JSON keys across hundreds of series and thousands
of issues costs about 1.5 MB; the same content as arrays with a lookup table
is a fraction of that.

### Publishing the dashboard

The dashboard lives at the repository root in `../docs/`, because GitHub
Pages can only serve a branch root or a `/docs` at that root. On GitHub:
**Settings → Pages → Source: `master` branch, `/docs` folder**. It has no
build step and no dependencies, so it also works by opening
`../docs/index.html` from disk.

Re-run Part 2's last two cells after new data, commit `../docs/data.js`, and
the published page updates.

## Things that look wrong but are deliberate

- **Seven dimensions have no total category** — causes of death, economic
  activity, employment status, main occupation, institutional sector, reasons
  for inactivity, the ICD list. An indicator broken down that way has no
  meaningful aggregate row, so its headline coverage is blank *by design*,
  not as a gap. `TOTAL_LABELS` in Part 2's config lists only the dimensions
  that do have one.
- **2027–2030 are excluded from the expected range.** They exist as
  projection columns in the template; counting them would make every country
  look incomplete.
- **Spikes are compared after collapsing to one value per series per year.**
  The same dimensions and year can appear twice in these files, and without
  that step the comparison pits two rows from the *same* year against each
  other.
- **`Value` is parsed with `to_number()` in Part 2, `clean_one_value()` in
  Part 1 — not `float()` in either.** Only 337 of 33,968 population cells
  are numeric; the rest are text like `' 701 956 '` using spaces as thousand
  separators. `to_number()` only needs a float-or-None for measuring tens of
  thousands of already-processed rows; `clean_one_value()` also has to
  explain, per cell, what it changed and why.

## What the checks have found

Numbers below are from the first real run after the two notebooks merged (10
September 2026), across Labor, Population and Poverty only — the three
chapters with a final file at the time. Re-run and update this after Health,
Education and Housing are added.

- **Two Population indicators labelled "(%)" hold absolute head-counts** for
  eight countries each, values up to 29,258,382. Both the `units` and the
  `total mismatch` checks find this independently. The single biggest data
  problem; needs fixing at source.
- **11,405 figures flagged**: 6,742 total mismatches, 1,553 implausible
  values, 1,317 percentage breakdowns not summing to 100, 965 spikes, 826
  conflicting duplicate rows, 2 units problems. Largely concentrated in Labor
  and Population's percent-labelled indicators, the same root cause as above.
- **325 of 1,206 series (27%) have never reported a single year.**
- **157 series report nothing after 2019.**

## Conventions

- `pandas` with `openpyxl`, `pathlib.Path` for every path — the paths contain
  spaces.
- The dashboard is vanilla HTML/CSS/JS with no dependencies, so it works
  offline and on Pages without a build step.
- Dark theme by design. Colours are validated steps: a single blue ramp for
  magnitude, status hues for severity, and every status also carries a word so
  nothing depends on colour alone.
- Read-only. If a change to the data is ever needed, it belongs in the
  pipeline project, not here — except Part 1's `apply_review()`, which
  changes exactly one thing (the dictionary and the value corrections file)
  and only on a person's own saved decision.
